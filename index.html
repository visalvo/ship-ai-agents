Mission A · Payout

Arithmetic in code, every number cited

Health policy, medical expenses. The MRI and the specialist visit are covered as outpatient care 1. Invoices €1,250, 20% co-insurance, minimum €100 2. The annual limit has €800 left 3. Proposed payout: €800.

1 · Policy §4.2 · p.12   2 · §4.2.b · p.12   3 · §7.1 · p.21

def calc_payout(amount: Decimal, terms: Terms) -> Payout:
    """Apply the cover terms to one claim.
    Terms arrive already resolved:
    only the clauses that apply."""
    share = max(amount * terms.coinsurance, terms.min_share)
    due = max(amount - share, ZERO)
    paid = min(due, terms.limit_left)
    return Payout(paid, cites=terms.clauses)

Four steps, two kinds of worker

  • Agent · extracts the terms from the policy and its endorsements, each with its validity dates.
  • Code · decides which clause wins and drops the ones that don't apply.
  • Agent · reasons on the claim and calls calc_payout with the terms that apply.
  • Code · checks every citation: the span must exist in the document, or the step retries.

The LLM reads and cites. Code computes and checks.

Mission A · Trust over time

What the eval loop caught

Caught · 01 · judge + human review

Ambiguous rules

Some coverage and payout rules were vague in the policy documents. Adjusters shared the real ones informally.

Fix · make them explicit with the business. New policies get a gap analysis first.

Feweragent errors, with the rules written down
Caught · 02 · golden set

Wrong articles retrieved

The right decision needs the right guarantee articles, and retrieval missed some.

Fix · the agent grades what it retrieves; retrieval is evaluated on its own.

Highershare of articles retrieved correctly
Caught · 03 · adjuster feedback

Too many escalations

Early versions were rigid: low confidence, so a human almost every time.

Fix · clearer rules, better prompts and tools, business rules in code.

Fewerescalations to a human, release after release

Every finding became a golden case. A regression can't sneak back in.

def confirm_plan(state: State) -> dict[str, Plan]:
    """Stop until the user confirms or edits the plan."""

Deep space

LOG · Everything works on launch day. The trouble starts in month three.

Production · Debugging with MLflow

The agent didn't crash. It kept trying.

What the model saw

run_sql → "query failed"

For a person, an annoying message. For the model, the whole prompt. So it guessed again.

Fixed outside the model

  • Tool. Returns the warehouse error: wrong column, wrong join
  • Middleware. Blocks the same call repeated, and says why
  • Limit. Two steps before the step limit, the agent stops, says what it tried, and asks

Production · Evaluation

Golden cases come from what went wrong

  • Where they come from. Plan corrections, thumbs-down, edited SQL, human overrides: the hardest cases in real traffic
  • A · before every release: amounts, outcome and confidence must not move; then judges check the approach and the cited documents
  • B · same data snapshot: expected query and result, dataframe against dataframe

The worst cases became rules in the prompt. A golden set doesn't just measure: it tells you what to write.

06

Return trip

What we're bringing home: what we'd do differently, and a checklist for your next launch.

LOG · Data secured. Heading home. Writing it all down for the next crew.

Takeaway 1 · Honest log

If we launched again tomorrow

Lesson · 01

Semantic layer first

The agent can't be smarter than your definitions. Agree on what "revenue" means, then build the agent on top.

Lesson · 02

A golden set on day one

Twenty real questions with checked answers beat a month of "looks good to me". It grows from there.

Lesson · 03

Tracing before the first user

Not after the first incident. You can't fix a loop you can't see.

Lesson · 04

Humans in the flow from the pilot

A human only at the end is easy to add. Finding the uncertainty points early is cheaper.

Takeaway 2 · Go / no-go

Pre-flight checklist

Will it be right?

Trusted

  • Tools as contracts, errors that say what next
  • Guarantees in middleware, not prompts
  • A golden set from day one
  • A human where it's uncertain or irreversible
Is it safe?

Secure

  • Acts as the user, read-only
  • Context curated by user, step, sensitivity
  • Documents and rows are data, never instructions
  • An audit log of who asked and what ran
Can we afford it?

Affordable

  • Cost per conversation, per release
  • Token budgets in middleware
  • A cache-aware context window
  • References back to the model, not rows
Can we run it?

Operable

  • Checkpoint, trace and version everything
  • Evals gate every release
  • Fallbacks, backoff, timeouts
  • An owner, an on-call, SLOs

Final message

None of the problems in this talk was fixed by a better model

Every one was fixed by a better ship: the infrastructure around the LLM.

We didn't stop worrying. We started measuring.
